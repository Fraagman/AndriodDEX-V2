# AndroidDEX-V2 — Complete Bug Report

**Method:** full line-by-line static read of all source: 48 Kotlin files (6,736 lines), 32 Rust files (7,461 lines), 5 `.proto`, Gradle/Kotlin build scripts, AndroidManifest + debug manifest, `res/xml`, `res/values`, proguard, packaging XML, PowerShell/batch scripts, and all 6 markdown docs.

**Limitation (honest):** this sandbox has no `cargo`, no JDK, no Android SDK/NDK, so **nothing was compiled or run**. Everything below comes from reading code. Items marked **[verify]** need a build/run on your machine to confirm — they are real risks but I could not prove them without a toolchain.

**Severity:**
- **P0** = app cannot be used / crashes / unsafe to ship
- **P1** = feature broken or user-visible failure in normal use
- **P2** = works but wrong, leaky, slow, or fragile
- **P3** = polish, dead code, docs, hygiene

## A. Desktop shell on the phone (windows, launcher, taskbar)

| # | Sev | Where | Bug (simple) | Fix (simple) |
|---|-----|-------|--------------|--------------|
| A1 | **P0** | `DesktopShell.kt:79,149` | `showLauncher` is only ever set to `false`. Nothing sets it to `true`. So on the streamed desktop there is **no way to open any app** — no Start button, no launcher, no taskbar. Only the PC's egui menu can open apps. | Add a Start button (or hotkey) that sets `showLauncher = true`, or draw `Taskbar` which already has one. |
| A2 | **P0** | `ui/components/Taskbar.kt` | The whole `Taskbar` (clock, connection dot, LIVE audio, settings button, back/home/recents) is **never rendered anywhere**. It is dead UI, and the manifest/accessibility strings talk about "the desktop taskbar" that does not exist. | Call `Taskbar(...)` from `DesktopShell` inside a `Column` under the windows, wire `onLauncherClick`, `onSettingsClick`, `onBack/Home/RecentsClick` to `DesktopAccessibilityService`. |
| A3 | **P1** | `ui/components/WindowChrome.kt:282-283` | Sizes are set in **dp** but the display is 1920**px** at 320dpi → 1dp = 2px. Maximize sets width `1920.dp` = 3840px, i.e. **twice the screen**; the default window `Rect(100,100,900,700)` = 800x600dp = 1600x1200px, taller than the 1080px display. Everything is oversized and clipped. | Do layout in px (use `Modifier.width(with(Density){dp.toPx()})` alternatives), or set `CAPTURE_DPI = 160` so 1dp = 1px, or size windows from `WindowState.bounds` px directly with `requiredSize(IntSize)`. |
| A4 | P2 | `WindowChrome.kt:276-277, 304-305` | Dragging changes a local `offsetX/offsetY` and **never writes back** to `WindowState.bounds`. Minimize→restore, or any recomposition that recreates state, teleports the window back to (100,100). | `ShellViewModel.moveWindow(id, dx, dy)` updating `bounds`, and initialise offset from `bounds`. |
| A5 | P2 | `WindowChrome.kt:300-308` | Drag has **no clamping** — you can throw a window off-screen and never get its title bar back; also no z-order/focus model, so clicks go to whichever window Compose hit-tests first, and the "active" window is unknowable. | Clamp `offsetX/offsetY` to `0..CAPTURE_* - size`, add `focusedId` + raise-on-click in `ShellViewModel`. |
| A6 | P2 | `vm/ShellViewModel.kt:33-49` | `openApp(packageName)` accepts **any** string (from the network and from an exported broadcast), never validates it against `AppRegistry`, and appends to a list with **no size limit**. Spamming it grows memory and creates windows that render nothing. | Reject unknown packages; cap windows (e.g. 16); return an error to the log/UI. |
| A7 | P2 | `vm/ShellViewModel.kt:33-40` | Second `openApp` of the same package returns early — so clicking a running app in the launcher **does not focus or restore** it (a normal desktop expectation), and a minimized window stays hidden forever. | On duplicate: un-minimize + raise instead of `return`. |
| A8 | P2 | `DesktopShell.kt:95-101` + `DesktopPresentation.kt:38-44` | "Force a redraw" hacks: a 10-frame loop that nudges a Box's size, plus a 500 ms `invalidate()` heartbeat. They exist because the encoder only produces frames when something is drawn — so the app fakes movement instead of telling the codec to repeat frames. | Set `MediaFormat.KEY_REPEAT_PREVIOUS_FRAME_AFTER` (≈500 ms) in `ScreenEncoder.buildFormat` and delete `burstTick`, `forceRedraw` and the heartbeat. |
| A9 | P3 | `ui/components/AppRegistry.kt` | All five `icon = null` → launcher shows coloured letter boxes; `AppConfig.icon` is dead; `AppIconCell`'s bitmap path is unreachable. | Load real icons (`packageManager.getActivityIcon`) or drop the field. |
| A10 | P3 | `ui/components/AppLauncher.kt:35` | `displayId` parameter is accepted and never used. | Remove it. |
| A11 | P3 | `AppLauncher.kt:40-42, 44-48` | Whole overlay is `.clickable { onDismiss() }` — clicking **anywhere**, including the app grid, first dismisses; there is no scrim vs content separation and no Back handling. | Put `clickable` on a background Box only, and add a `BackHandler`. |
| A12 | P3 | `service/DesktopPresentation.kt:69-73` | `onCreate` clears `FLAG_NOT_FOCUSABLE`/`FLAG_ALT_FOCUSABLE_IM` on the Presentation window; on an untrusted virtual display this has no IME to help and it changes system window policy for no gain. | Keep default flags unless you can show what they fix. |
| A13 | P3 | `service/DesktopPresentation.kt:150-152` | `onResume()` is called manually right after `show()`, and `dismiss()` fires `ON_DESTROY` on a `LifecycleRegistry` the ComposeView may still be reading. | Let `Presentation` drive the lifecycle; call `onPause()` before `onStop`. |

## C. Video pipeline on the phone

| # | Sev | Where | Bug | Fix |
|---|-----|-------|-----|-----|
| C1 | **P1** | `DisplayService.kt:288-300` (`reconfigureResolution`) | If `encoder.prepare()` fails at the new size, the function `return`s — the old encoder is already released and the VirtualDisplay is left with a dead surface. Result: **permanent black screen**, no retry, no fallback to the old resolution, notification still says "Display active". | Keep the old encoder alive until the new one is configured; on failure re-attach the old surface and restore the old size. |
| C2 | **P1** | `video/ScreenEncoder.kt:103-113` (`prepare`) | On the profile-retry path, if the **second** `configure()` also throws, the `MediaCodec` created at line 100 is never released → leaked hardware codec. | C3 | **P1** | `DisplayService.kt` (whole class) | Encoding never stops when the PC disconnects. The encoder keeps burning at 12 Mbps forever; only the queue drops. `MainActivity.kt:170-184` stops `DisplayService` — but only while the **control panel** is composed, not while the desktop Presentation is showing. | Drive the pipeline from the QUIC state: on leaving `STATE_AUTHENTICATED`, `pause()` the encoder (or stop the pipeline) and resume on reconnect. |
| C4 | P2 | `DisplayService.kt:45-47` | `CAPTURE_WIDTH/HEIGHT/BIT_RATE` are mutable `var`s on a companion object: written from the Settings app (Compose thread) and read from the MediaCodec callback thread, with **no `@Volatile`/lock** → torn reads and stale values are possible, and `updateResolution` can race with `reconfigureResolution`. | Put the settings in one `@Volatile` immutable `data class PipelineConfig` swapped atomically. |
| C5 | P2 | `DisplayService.kt:66-73, 131` + `onDestroy` | `instance = this` in `onCreate`, **never cleared** in `onDestroy` → a destroyed Service (and its Context) is held by a static forever; `forceRedraw`/`encoderStats` are also global mutable state on the companion. | `onDestroy { instance = null }`, or inject the service rather than a static. |
| C6 | P2 | `DisplayService.kt:158-166` (`onStartCommand`) | `startEncodingPipeline()` runs in `onCreate` **and** `onStartCommand`; `startForegroundWithNotification()` only in `onStartCommand`. | C10 | P2 | `video/ScreenEncoder.kt:15, 189` | Comment: "Required for zero-copy… no pixel copy anywhere in this class" — accurate for the codec input, but the class doc above it says the output "never enters application memory", which is false (it does, 3 times, see C7). | Fix the comment or fix the code. |

## E. Phone↔PC wire protocol & native QUIC server

| # | Sev | Where | Bug | Fix |
|---|-----|-------|-----|-----|
| E1 | **P1** | `rust_quic_server/src/lib.rs:276` (`unbounded::<Vec<u8>>()`) + `service/InputManager.kt:36-44` | The input queue is **unbounded**, capped only at 64 KB *per event*, and Kotlin consumes **one event per JNI poll** (each poll also blocks up to 20 ms). A receiver that sends fast (mouse at 1 ms + key repeat + scroll) grows the phone's heap → OOM kill, and input latency climbs instead of staying bounded. | Use a bounded channel with drop-oldest (reuse `FrameQueue` with capacity e.g. 64) and batch events per poll (`try_recv` loop). |
| E2 | **P1** | `lib.rs:76-84` + `service/InputManager.kt:56-70` | No rate limit on **input events** at all (only *pairing* is rate limited). 100 k MotionEvents/s flood the main thread → ANR on the phone, from a device that paired once and reconnects without any prompt. | Token-bucket events/sec in `read_input`, and drop on exceed instead of forwarding. |
| E3 | P2 | `lib.rs:309-326` (`bind_endpoint`) | The "avoid EADDRINUSE after force-stop" fallback sets **`SO_REUSEADDR` on a UDP socket** — on Android/Linux that does **not** let you take over a bound port (that's `SO_REUSEPORT`), so the fallback almost never rescues the bind. The comment overstates it. | On shutdown, actually close the endpoint (`Endpoint::close` + drop); or use `SO_REUSEADDR` **before** the first bind and document the real semantics. |
| E4 | P2 | `quic/QuicServer.kt:14-19` | If native `start()` fails it returns `0` and `startServer` only logs at `Log.d` — **the app silently runs with no server**: the PC can never connect, and the phone's UI shows "Idle" forever. No user-visible error, no retry. | Return a result; show a terminal error in the UI ("port 4433 busy / bind failed") with a Retry button. |
| E5 | P2 | `quic/QuicServer.kt` (whole file) | There is **no `stop()`**. The runtime, endpoint and accept loop leak for the process lifetime; `SERVER: OnceLock` means the port can never be re-bound or moved; and a restart of `DisplayService` reuses a half-dead server. | Add `nativeStop(handle)` that closes the endpoint, shuts down the runtime and resets `handle`; keep `OnceLock` only if the process is the unit of restart. |
| E6 | P2 | `lib.rs:690-700` (`pollData`) | The event is **popped from the queue first**, then dropped if it doesn't fit the Kotlin buffer (`data.len() > capacity → return 0`) — the input event is lost forever and the caller sees "nothing to do". | Peek capacity first, or size the buffer from the length; never discard after dequeue. |
| E7 | P2 | `lib.rs:86-90` (`session_lock`) | Only one session may stream; a second PC **waits on a mutex forever** with the connection open and no explanation (no close code, no status). Symptom: "second monitor connects but shows nothing". | Close the second connection with a dedicated code (`CLOSE_BUSY`) and show "another PC is already streaming" on the receiver. |
| E8 | P2 | `lib.rs:129-146` (`check_pairing_rate_limit`) | Comment says the map overflow path removes "the oldest key", but `map.keys().next()` is an **arbitrary** HashMap entry → the eviction is not LRU and the comment is wrong. Also a client can dodge the limiter by rotating its source address. | Keep a `VecDeque<IpAddr>` insertion order, or `Instant`-sorted eviction; and apply the limiter to `authenticate_and_serve` too (currently unthrottled). |
| E9 | P2 | `frames.rs` + `zc-core/src/main.rs` | Audio queue depth is 8 packets (~160 ms) but the **receiver ignores `pts_us` completely** (`main.rs:521-527` decodes as fast as it arrives) and has no pacing/jitter buffer. Audio has its own 60 ms catch-up, video has none → any stall desynchronises lips and never recovers. | Use `pts_us` to pace video presentation and align audio to it (a 30-80 ms jitter buffer). |
| E10 | P2 | `store.rs:143-166` (`write_private`) | Atomic-ish write via `with_extension("tmp")`: for `tls_identity.bin` the temp is `tls_identity.tmp`; two files with the same stem would collide, and the containing **directory is never fsynced** after `rename` → after a crash the rename may be lost while the file is gone.

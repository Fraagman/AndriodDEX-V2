**Extra bugs found in section-A components (will fix):**
- **E1 (P2):** duplicate `OPEN_APP` receivers — `MainActivity.kt:150-165` *and* `DisplayService.kt:118-137`, both `RECEIVER_EXPORTED`; one ADB broadcast + the QUIC event = up to 3 `openApp` calls per launch. Remove MainActivity's (DisplayService's lives with the streaming session).
- **E2 (P2):** raw package name as window title (fixed by A6 registry lookup).
- **E3 (P3):** `DesktopShell.kt` polls `framesSent` but never reads it (dead state) — remove.
- **E4 (P2):** exported receivers accept arbitrary strings from any phone app — closed by A6 validation.

## Implementation (4 batches, phone-side only; receiver untouched)

**Batch 1 — Window system: A3, A4, A5, A6, A7, E1, E2**
- `DisplayService.kt`: `CAPTURE_DPI = 160` (density 1.0 → 1 dp = 1 px; makes every existing dp value correct at once — minimal and consistent with the author's px-intent of `bounds`/taskbar-48px).
- `ShellViewModel.kt`: `openApp(packageName)` — validate against `AppRegistry`, take title from registry, cap 16 windows (reject + log), duplicate → un-minimize + raise; new `moveWindow(id, dx, dy)` with clamping (x ∈ [−(w−100), CAPTURE_WIDTH−100], y ∈ [0, CAPTURE_HEIGHT−100]); `raiseWindow(id)` (move to list end = z-order top); `focusedId` = last non-minimized window, exposed as StateFlow.
- `WindowChrome.kt`: delete local offset `remember` — position comes from `windowState.bounds`; drag deltas → `vm.moveWindow` (write-through, teleport bug gone); raise-on-press via `pointerInput(detectTapGestures onPress)` on the outer Box + raise on drag start; focused/unfocused title-bar tint.
- `MainActivity.kt`: remove duplicate receiver (E1).

**Batch 2 — Shell UI: A1, A2, A10, A11, E3**
- `DesktopShell.kt`: compose `Taskbar` (bottom-center, drawn *above* the launcher scrim so Start toggles the launcher); `onLauncherClick = { showLauncher = !showLauncher }`; `onSettingsClick` → `openApp("com.androiddex.settings")`; nav buttons → `DesktopAccessibilityService.performBack/Home/Recents()`, visible only when `a11yEnabled`; delete `forceRedraw`/`burstTick` hack and dead `framesSent`; drop `displayId` parameter chain.
- `AppLauncher.kt`: remove `displayId`; clickable on background Box only; add `BackHandler`.
- `DesktopPresentation.kt`: update call site (no `displayId`).

**Batch 3 — Icons: A9**
- `AppRegistry.kt`: `icon: ImageVector?` with real Material icons per app.
- `AppLauncher.kt`: `AppInfo.icon: ImageVector?`; `AppIconCell` renders the vector directly (bitmap fallback for `null` stays as the letter box).

**Batch 4 — Encoder + presentation: A8, A12, A13**
- `ScreenEncoder.kt` `buildFormat`: `KEY_REPEAT_PREVIOUS_FRAME_AFTER = 500_000` (µs).
- `DesktopPresentation.kt`: delete heartbeat; `clearFlags` → only `FLAG_DIM_BEHIND`; add `onPause()`; `dismiss()` order = `ON_PAUSE` → `super.dismiss()` (framework `ON_STOP`) → `ON_DESTROY` + `store.clear()`; keep manual `onResume()`.
- `DisplayService.kt` + `InputManager.kt`: delete `forceRedraw` and all bump sites (window state changes drive recomposition naturally; requested IDRs materialize on the next repeated frame ≤ 500 ms).

## Testing (device 2c0f6edc, everything verified before claiming done)
1. `gradlew installDebug`, launch app.
2. **A8 gate:** static screen, no client → logcat `encode` must show steady ~2 fps. If 0 fps → encoder ignores the key → restore heartbeat/forceRedraw and report honestly.
3. **A3 sizing:** `screencap -d <virtual display id>` → taskbar 48 px, opened window 800×600 at (100,100), maximize fits 1920×1032, nothing clipped.
4. **Behavior** via the existing `DebugDesktopActivity` harness (built exactly for `adb input`/`screencap` testing): Start opens/closes launcher; app opens with title "Settings"; broadcast twice → one window, raised; unknown package → rejected; 30 broadcasts → ≤16 windows; drag moves + clamps; minimize→restore keeps position; click switches focus tint.
5. **End-to-end:** restart receiver → first frame on a static screen arrives as an IDR within ~1 s; stream renders; A12 verified by PC input still controlling the shell (direct-dispatch path), final confirmation by you moving the mouse.
